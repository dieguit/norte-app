# TanStack Start Folder Structure

Research completed 2026-08-16 using official TanStack documentation and the official TanStack Router repository.

## Recommendation

Use `src/routes` as the route/page boundary, colocate route-specific components and domain code near the route that consumes them, and keep reusable cross-route code in explicit domain folders. Put database and other server-only implementation behind `.server.*` modules or a `createServerFn` boundary. Treat `routeTree.gen.ts` as generated output, not a hand-edited source file. This is a synthesis of the conventions and examples below, not a single mandated TanStack directory template. ([Routing](https://tanstack.com/start/latest/docs/framework/react/guide/routing), [Import Protection](https://tanstack.com/start/latest/docs/framework/react/guide/import-protection), [Trellaux source tree](https://api.github.com/repos/TanStack/router/contents/examples/react/start-trellaux/src))

## Key Findings

1. **Routes/pages belong in `src/routes`.** TanStack Start uses TanStack Router file-based routing; files and directories under `src/routes` represent the route hierarchy, with `__root.tsx` as the always-matched root and `index.tsx` as the home route. File-based routing is documented as the preferred routing approach and provides automatic code-splitting and generated type linkages. ([Start routing guide](https://tanstack.com/start/latest/docs/framework/react/guide/routing), [Router file-based routing](https://tanstack.com/router/latest/docs/framework/react/routing/file-based-routing))

2. **Use route conventions to express URL structure, not arbitrary component organization.** `index.tsx`, `$param.tsx`, `$.tsx`, pathless layouts, grouped routes, and flat or directory forms have defined meanings; flat and directory routes may be mixed. Keep route files aligned with URL and layout boundaries, then colocate route-specific view code beside them when that improves locality. ([Router file-based routing](https://tanstack.com/router/latest/docs/framework/react/routing/file-based-routing))

3. **Colocation is compatible with the official example shape.** The official `start-trellaux` example separates `routes`, `components`, `db`, `hooks`, `icons`, `styles`, and `utils` under `src`, alongside `router.tsx` and `types.ts`; this demonstrates domain/concern folders close to the application entry point without requiring a single global `components`-only architecture. ([Official Trellaux source tree](https://api.github.com/repos/TanStack/router/contents/examples/react/start-trellaux/src))

4. **Do not assume route loaders are server-only.** TanStack Start is isomorphic by default, and route loaders run on the server during SSR and on the client during navigation. Server-only work such as secrets, filesystem access, database connections, and private API keys should therefore be called through `createServerFn()` or protected with `createServerOnlyFn()`. ([Execution model](https://tanstack.com/start/latest/docs/framework/react/guide/execution-model))

5. **Make the server boundary visible in filenames and modules.** Start's default import protection denies `*.server.*` files in the client environment and `*.client.*` files in the server environment. A practical boundary is therefore `src/features/<domain>/...server.ts` for server implementation and a separate client-safe entry point that exports the callable `createServerFn` wrapper. ([Import Protection](https://tanstack.com/start/latest/docs/framework/react/guide/import-protection))

6. **Avoid mixed client/server barrels.** The official import-protection guidance recommends splitting safe exports from server-only exports into separate entry points, because a barrel that re-exports both can expose an unsafe import edge to client-reachable code. ([Import Protection, “Mixed Barrels and Split Entry Points”](https://tanstack.com/start/latest/docs/framework/react/guide/import-protection#mixed-barrels-and-split-entry-points))

7. **Keep generated route files out of the hand-maintained source model.** `src/routeTree.gen.ts` is automatically generated by Start during development/start and contains the route tree plus TypeScript utilities; the Router plugin or CLI also manages route path strings in `createFileRoute` declarations. Do not edit this file manually, and do not use it as the place for domain logic. ([Start routing guide](https://tanstack.com/start/latest/docs/framework/react/guide/routing), [Router file-based routing](https://tanstack.com/router/latest/docs/framework/react/routing/file-based-routing))

## Suggested Shape

```text
src/
├── routes/                         # URL and layout boundaries
│   ├── __root.tsx
│   ├── index.tsx
│   └── accounts/
│       ├── index.tsx
│       └── $accountId.tsx
├── features/                       # reusable domain code, colocate when route-specific
│   └── accounts/
│       ├── AccountSummary.tsx
│       ├── account.server.ts        # database/server implementation or server-only helpers
│       └── account.ts                # client-safe server-function entry point, if needed
├── components/                     # genuinely cross-domain UI
├── router.tsx
└── routeTree.gen.ts                 # generated; never hand-edit
```

The shape above is an application-level recommendation derived from the documented route boundary, server import rules, and official example structure; TanStack does not prescribe these exact `features` or `components` directories. ([Start routing guide](https://tanstack.com/start/latest/docs/framework/react/guide/routing), [Import Protection](https://tanstack.com/start/latest/docs/framework/react/guide/import-protection), [Trellaux source tree](https://api.github.com/repos/TanStack/router/contents/examples/react/start-trellaux/src))
